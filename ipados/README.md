# Ferdium for iPadOS (Strategy A)

Native Swift + `WKWebView` shell that runs the Ferdium renderer on iPadOS.

> Apple does not allow Electron/Chromium/Node.js on iPadOS, so this is **not** a
> rebuild of the macOS Electron binary. It is a native app that reuses the web UI
> layer. See [`docs/ipados-port.md`](../docs/ipados-port.md) for the full design,
> capability matrix, and phased plan.

## Layout

```
ipados/
  project.yml                       # XcodeGen project spec (text-based, reviewable)
  scripts/bundle-renderer.sh        # esbuild renderer -> app bundle
  Ferdium-iPadOS/
    App/        FerdiumApp, AppDelegate, RootView   # app lifecycle (≈ Electron main)
    Host/       HostWebView                         # hosts the React renderer
    Services/   ServiceWebViewManager, …            # one isolated WKWebView per service
    Bridge/     PlatformBridge, NotificationBridge, # native ⇄ renderer + capabilities
                DownloadBridge, LocalStore, BridgeScripts
    Resources/  Info.plist, entitlements,
                bridge/platform-bridge.js           # window.ferdiumNative shim
                bridge/recipe-bridge.js             # window.ferdium + notification patch
    Renderer/   (generated by bundle-renderer.sh — gitignored)
```

## Build

```bash
./ipados/scripts/bundle-renderer.sh   # build + copy the renderer
cd ipados && xcodegen generate        # needs: brew install xcodegen
open Ferdium-iPadOS.xcodeproj         # build/run from Xcode
```

Set `DEVELOPMENT_TEAM` in `project.yml` (or via Xcode signing) before running on a
device. CI builds an unsigned simulator app in `.github/workflows/ipados.yml`.

## Status

Foundational scaffolding for phases 1–2 (host webview, per-service isolation,
bridge, notifications, downloads, local store). The native target compiles a
shell; full service parity, the local-API port, and UX hardening are tracked as
later phases in [`docs/ipados-port.md`](../docs/ipados-port.md).
